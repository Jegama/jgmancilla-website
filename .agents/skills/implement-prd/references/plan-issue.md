# Plan an existing GitHub issue

Use this when the deliverable is a plan or when requirements need a handoff before implementation. Read the issue and relevant comments, trace its premise to current behavior, and locate existing code that could satisfy all or part of the request. Cite the decisions and code that materially affect scope.

Return Markdown suitable for the existing issue:

- **Outcome and scope.** Describe what will change for the user and any agreed exclusions.
- **Acceptance criteria.** Give an observable result for each requirement.
- **Approach and verification.** Identify the smallest deliverable, dependencies, existing mechanisms to reuse, and how to check it.
- **Open decisions.** Name the choices that actually need the owner, and any independent work that can proceed first.

When the issue spans independent deliverables, suggest a split and explain the dependency or benefit. Leave the plan in the response unless asked to save or publish it. If asked to update an existing issue, preserve prior requirements and discussion.
